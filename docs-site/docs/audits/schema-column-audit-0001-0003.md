## JSONB column shapes

The following columns use JSONB storage. The shape descriptions are derived from the DDL comments
and the client source referenced in the respective rows. All JSONB values are stored verbatim
(byte-faithful round-trip per BD-DOCS-031) — no server-side normalization is applied in Phase-1.

### `posts.tags` (Row 35)

Ordered tag array from `posts.v1 tags` and `myposts tags:[category,location]`; JSONB preserves order and variable length; no GIN index yet (tag-search is UI-only/no-op today).

**Shape:** `string[]` — array of tag strings, e.g. `["Москва", "Грузовой"]`. Variable length; order-preserving. GIN index deferred (tag-search UI-only today).

### `orders.pickup` (Row 49)

Nested pickup object `{lng, lat, label?}` persisted verbatim from the client; typed geo columns deferred to Phase-3 (#4 PostGIS). Nullable — not all orders carry a resolved pickup.

**Shape:** `{lng: number, lat: number, label?: string}` or `null`. Nested object from the Mapbox route picker; `label` is the human-readable address string. Typed geo columns deferred to Phase-3 PostGIS.

### `orders.dropoff` (Row 50)

Nested dropoff object `{lng, lat, label?}` persisted verbatim; same PostGIS-deferred rationale as `pickup`.

**Shape:** `{lng: number, lat: number, label?: string}` or `null`. Same shape as `pickup`.

### `orders.passenger_snapshot` (Row 60)

Sanitized passenger snapshot `{name,initials,phoneMasked,comment,authorId,isCurrentUser}` from `createRideOrder`; JSONB so the BD-ACTIVE-07 driver handoff reads it verbatim. `isCurrentUser` is PER-VIEWER state — API MUST recompute per authenticated request.

**Shape:** `{name: string, initials: string, phoneMasked: string, comment: string, authorId: string, isCurrentUser: boolean}` — the `createRideOrder` sanitized snapshot. **WARNING:** `isCurrentUser` is PER-VIEWER state — the API must recompute it per authenticated session and never echo the stored flag to a different viewer.

### `responses.driver_snapshot` (Row 77)

JSONB snapshot `{name,rating,car,carModel,carColor,plate}` from `respond.js`; stored verbatim so the `/responses` card renders the driver card byte-faithfully without re-querying users/vehicles.

**Shape:** `{name: string, rating: string, car: string, carModel: string, carColor: string, plate: string}` — from `respond.js driverSnapshot`. Note `rating` is a localized TEXT string ('5,0'), not a number.

### `rides.order_tags` (Row 136)

Order tag array from `ride.order.tags`; JSONB string array; shown on the driver's order-detail card for trip attributes (e.g. pet, luggage).

**Shape:** `string[]` — trip attribute tags (e.g. `["Питомец", "Багаж"]`). Nullable; shown on the driver's order-detail card.

### `rides.feedback_tags` (Row 155)

Passenger's rating tag array from `ratingPayload.tags`; JSONB; nullable when no tags were selected; surfaced by Profile history card.

**Shape:** `string[]` — passenger rating tags (e.g. `["Чисто", "Вежливо"]`) from `ratingPayload.tags`. Nullable; surfaced by Profile history card.

### `ride_events.payload` (Row 196)

Full original record stored losslessly; ensures the append-only timeline can replay either producer shape without column drift as fields evolve. Always present (DEFAULT '{}' for empty payloads).

**Shape:** Full original record losslessly stored. For `type='trip_confirmation'`: the complete `trip_confirmation.v1` handoff object. Default `'{}'::jsonb` when no extra payload.
