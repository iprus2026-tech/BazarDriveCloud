## JSONB column shapes

The following columns use JSONB storage. Shapes are derived from executable browser and server code
at the pinned SHA, not from migration comments alone. JSONB handling is not uniformly verbatim:
the orders service validates point objects, sanitizes `passenger_snapshot`, and the implemented
ride-event writer emits a focused `{from,to}` payload.

### `posts.tags` (Row 35)

Ordered tag array from `posts.v1 tags` and `myposts tags:[category,location]`; JSONB preserves order and variable length; no GIN index yet (tag-search is UI-only/no-op today).

**Shape:** `string[]` — array of tag strings, e.g. `["Москва", "Грузовой"]`. Variable length; order-preserving. GIN index deferred (tag-search UI-only today).

### `orders.pickup` (Row 49)

The [DDL declaration](https://github.com/iprus2026-tech/BazarDriveCloud/blob/f4ccf801ec2c248840c64216a5168cb4b7598958/server/migrations/0001_phase1_init.sql#L267-L270)
is nullable and has no `jsonb_typeof` (or equivalent) CHECK. Direct database/import writes may
therefore store any JSONB value — object, array, string, number, boolean, or JSON `null` — or
SQL `NULL` (no importer is implemented at the pinned SHA). The live
[POST request contract](https://github.com/iprus2026-tech/BazarDriveCloud/blob/f4ccf801ec2c248840c64216a5168cb4b7598958/server/src/services/orders/index.js#L14-L64)
instead requires the `pickup` property and a non-null POINT object with a non-empty `label`.
It accepts optional `id`, `hint`, `source`, `coords`, `lng`, and `lat`; `coords`
is restricted to object, array, or null, while additional properties remain allowed.

**DDL/storage constraint:** any JSONB value or SQL `NULL`; the intended object shape is not enforced.

**Live POST shape:** `{label: string, id?: string|null, hint?: string, source?: string, coords?: object|array|null, lng?: number, lat?: number, ...}` — non-null root.

### `orders.dropoff` (Row 50)

The same unconstrained nullable [JSONB declaration](https://github.com/iprus2026-tech/BazarDriveCloud/blob/f4ccf801ec2c248840c64216a5168cb4b7598958/server/migrations/0001_phase1_init.sql#L267-L270)
applies to `dropoff`: direct database/import writes may store any JSONB value or SQL `NULL`.

**DDL/storage constraint:** any JSONB value or SQL `NULL`; the intended object shape is not enforced.

**Live POST shape:** `{label: string, id?: string|null, hint?: string, source?: string, coords?: object|array|null, lng?: number, lat?: number, ...}` — non-null root.
