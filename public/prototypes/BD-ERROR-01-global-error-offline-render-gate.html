Screen Contract Notes
  • Singleton overlay owned by the app shell — mounted above #app inside #shell, one instance for the whole app.
  • Driven by a global connection / lastError store — screens do not own these states; they read connection state from the shell.
  • Banners are non-blocking — offline (state 1) and retrying (state 4) pin to the top and leave the screen interactive and scrollable.
  • Server error and timeout cards use a scrim and trap interaction until Повторить or a dismiss action (Поддержка / Позже).
  • Recovered toast auto-dismisses (~3s) and requires no action.
  • Повторить re-runs the last failed action — it does not reload the whole app or reset navigation.
  • Never mutates ride / order state — this layer is read-only with respect to trips, orders, and payments.
  • Must not suppress a screen's own inline empty / loading / error states — those remain per-screen; this gate is additive.
  • Transport-level failures only — offline, timeout, 5xx. Not validation errors, not business rejects, not Mapbox tile errors.
  • Connection state is mock / navigator.onLine in implementation — no backend, no real push, no socket.
